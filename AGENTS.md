# Agent operating instructions

## Portfolio standing instruction — one active task per agent (2026-11-16)

- **WIP limit: 1.** Each individual agent (including agents acting through OpenClaw, Cursor, Codex, or Claude) may own **one ACTIVE task across the entire portfolio**. Before work starts, the canonical GitHub issue/work order must identify the agent, deliverable, target environment, **specific deadline with timezone**, and acceptance proof. Do not create parallel tasks or exploratory side quests to evade this limit.
- **No new work** for that agent until the existing task is explicitly marked **DONE** or **CUT** in the canonical issue and portfolio board. **BLOCKED, IN REVIEW, or WAITING** are not DONE and still consume the agent's slot. Escalate only the smallest material founder decision or permission needed to unblock it.
- **DONE means shipped and verified, not diagnosed.** For a release task: accepted code merged; authorized production deployment reachable at its real URL; end-to-end smoke check against the served version; actual deployment SHA, evidence links and rollback recorded. A PR, passing tests, static mockup, preview URL, report, or claim of readiness alone is not DONE. For non-public infrastructure, specification, or research tasks, use an equally concrete *authorized* operational or publication destination—not an invented Product Hunt launch.
- **CUT means a recorded cancellation/deferral decision**, with reason, owner, and disposition of unfinished work; abandoning or renaming a task is not CUT.
- Work the shortest safe critical path to the assigned deliverable. Investigate only blockers necessary for that task; do not substitute repeated diagnostics, architecture expansion, or status updates for execution. Preserve existing repository contracts, CI, privacy controls, and independent verification.
- This standing rule **does not grant permissions** for production promotion, external sending, data mutations, or release where existing repo rules require founder authorization. **Every purchase or incremental financial spend requires explicit founder approval.** When those approvals are absent, keep the task active/blocked or cut it; never falsely mark it done.
